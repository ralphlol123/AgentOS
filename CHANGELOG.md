# Changelog

All notable changes to AgentOS for Projects are documented here.

## [Unreleased]

### Fixed

- Hints that still pointed at `agentos brain init` (removed in 3.0.0) now name the 3.0 command: the `init --dry-run` plan line ends with "list them after init with `agentos brain list`", a failed Brain setup during `init` says "Fix it, then re-run `agentos init`", and an empty `brain list` and the Obsidian index note's empty Brain list say to re-run `agentos init` (or `agentos brain register <path>`). An index note written with the old empty-list line is still recognised as generated. `docs/release-readiness.md` uses `skills add <file>` instead of `templates import`, and `docs/reliability-acceptance.md` describes `run handoff` and `templates list` as removed.
- A guard test runs help, every `<command> --help`, `init --dry-run`, an empty `brain list`, `doctor`, `status --full` and every file `init` generates, and fails if any names a removed form. The forms come from `src/removed-forms.ts`, the same table the CLI refuses them with.
- `agentos agents sync claude-code` writes `Edit(…)` permission rules only. It wrote every denied path three times (`Edit`, `Write`, `NotebookEdit`), and Claude Code 2.1.311 warns on every start that each `Write(…)`/`NotebookEdit(…)` rule never matches ("use Edit(…)"), since Edit rules apply to every file-editing tool. The deny rules were trial-verified on Claude Code 2.1.310 with all three kinds; Edit-only coverage rests on Claude Code's own warning, not a new trial. A plain re-sync removes the `Write(…)`/`NotebookEdit(…)` entries its sync record owns and keeps owner-added rules; until then `doctor` and `context --require-synced-config` report `Synced config: STALE — re-run agentos agents sync claude-code --role <id> … (.claude/settings.local.json: Write/NotebookEdit rules Claude Code no longer matches)`. Existing workspaces: `agentos agents sync claude-code --role <id> [--scope …]` once after upgrading.

## [3.1.0] - 2026-10-27

### Added

- `agentos upgrade [--check] [--to <version>] [--dry-run] [--yes] [--json]`: finds the latest version on the npm registry (`AGENTOS_REGISTRY_URL` for mirrors, 10 s timeout), detects how this CLI was installed (Bun/npm/pnpm global, project-local, unknown), runs that manager's global install, verifies `agentos --version` on PATH is the target, then runs the new binary's `doctor --fix` in the current workspace. `--check` exits 0 up to date / 10 update available / 1 error. Asks first on a terminal; without a terminal it needs `--yes`, and a major version always needs `--yes` or a typed `yes`. Project-local and unknown installs refuse and print the command to run. Installer failure or a version mismatch stops before the workspace refresh.
- `build`, `prepare` and `prepack` delete `dist/` before compiling, so stale files from removed sources can no longer be packed.

## [3.0.0] - 2026-10-27

### Breaking changes / Removed

3.0.0 removes every form deprecated in 2.1 and the legacy upgrade paths deprecated since 0.9.0. A removed form exits 1 with one stderr line, `agentos <x> was removed in 3.0.0; use <new>`, and writes nothing (also with `--help`). Table: `docs/migration-3.0-cli.md`. **Older workspaces that still need a legacy migration: run `npx agentos-for-projects@2 doctor --fix` once first** (the 2.x line keeps every legacy migration), then upgrade.

- `handoff` → `status --full`.
- `run handoff` → `checkpoint --task <id>` and `resume --task <id>`.
- `prompt [engine]` → `context [engine] --brief` (byte-identical output).
- `adapters explain <file>` → `doctor --explain <file>`.
- `engines [--json]` → `doctor --engines [--json]`.
- `templates list|show|copy|validate|import` → `agents|skills list`, `agents|skills show <id>`, `agents|skills add <id>`, `agents|skills add <file> --dry-run`, `agents|skills add <url|file>`.
- `link-obsidian` → `obsidian link --note <path>`; `obsidian link-workspace` → `obsidian link --no-index`.
- `brain validate` → `brain preview`; `brain init` (workspace) → `init` (`brain init --location vault` stays).
- `agents manifest <id> --from-catalog` → `doctor --fix` (`agents manifest <id> --custom` stays).
- `compact --checkpoint` → `compact --archive-only`; `compact --rewrite` → `compact`.
- `skills add --mode summary|full` → `skills add` (catalog cards are always complete; an imported skill keeps a summary excerpt; `--mode full` imports are gone).
- `init --agents detected` → `init --agents minimal` (same team; also the default).
- `doctor --fix --adopt-custom-adapters` → `npx agentos-for-projects@2 doctor --fix --adopt-custom-adapters` once (or by hand); a plain `doctor --fix` refuses an `adopt` adapter with zero writes and names both.
- `doctor --fix --prune-retired`, and the migration of byte-matched retired agent cards by plain `doctor --fix` → `npx agentos-for-projects@2 doctor --fix [--prune-retired]` once, or `agents add <canonical>` / `skills remove` + `skills add`. Retired IDs in `project.yaml` are still resolved to the canonical IDs.
- `doctor --fix --normalize-repo-ids` → `npx agentos-for-projects@2 doctor --fix --normalize-repo-ids` once, or rename the key and `.agentos/repos/<id>.md` by hand.
- `migrate claude --preserve` → `npx agentos-for-projects@2 migrate claude --preserve` once, or rename the `.claude` files by hand.
- The 2.1 `Deprecated:` notices, the `deprecations` field of `--json` output and `migration.deprecations` in `doctor --json` are gone. The read-only `migration` inventory stays; retired cards are classified `manual-review` (or `index-only`) and every `next` names the manual step or the 2.x command.
- Library (`dist/core.js`, not a public API): `templatesAgentOS`, `runHandoffAgentOS`, `migrateClaudeAgentOS`, `normalizeRepoIdsAgentOS` removed; `compactAgentOS` takes `archiveOnly` instead of `checkpoint`/`rewrite`.
- Deleted modules: `src/legacy-deprecation.ts`, `src/legacy-skill-shapes.ts`.
- Still read unchanged: configs written by removed commands (`knowledge.obsidian.mode: link-only`; `mode: workspace-folder` with an absolute `vault` in `project.yaml` and no `canonical`/`index`), skill cards written with `mode: full`, legacy agent cards from `templates import`.

### Added

- **Autonomous Brain mode.** `knowledge.brain.approval.mode: autonomous` (owner-set; `actors` required, optional `records` and `exclude`) lets an allowed agent apply its own proposal with `agentos brain apply <proposal> --auto --by <self>` for any workspace record kind, `replace` or `append`, including supersession. Still refused and left pending: validation rejections or conflicts, vault-canonical or excluded records, a checkpoint with an `observed-fail` receipt, bodies over 64,000 bytes. Applied proposals record `approval_mode: autonomous`; an invalid policy behaves as manual. Under this policy, the adapters, guide, checkpoint footer and context rules tell engines to apply their own proposals (run `agentos doctor --fix` after changing it). `manual` and `auto-append` are unchanged. See `docs/brain.md#autonomous-mode`.
- **Brain snapshots.** Every apply (any mode) saves the target's previous file to `.agentos/brain/history/<record>/<body sha256>.md`. The history line now ends with `; approval <mode>`.
- **`agentos brain revert <id> --last|--to <hash> --by <name> [--auto] [--force] [--dry-run]`** restores a snapshot under the writer lock, snapshots the replaced version (so a revert is revertible), and refuses missing or mismatched snapshots and hand-edited records unless `--force`.
- **`agentos brain log [<id>]`** lists recent applies and reverts with actor, approval mode and hashes.
- **The 11-command CLI** (`init`, `status`, `doctor`, `context`, `checkpoint`, `resume`, `brain`, `agents`, `skills`, `obsidian`, `compact`). New forms: `status --full`, `context [engine] --brief` (byte-identical to `prompt`), `context --strict` (= `--require-synced-config --require-enforcement --require-complete`), `doctor --explain <file>`, `doctor --engines [--json]`, `obsidian link --note <path>` (exact-note link-only mode, same prompts), `obsidian link --no-index`, `compact --archive-only`. Old → new: `docs/migration-3.0-cli.md`.
- **`agents add <file|url>` and `skills add <file|url>`** run the safe import (hash pin with `--expected-sha256`, safety review, quarantine of BLOCK findings, no overwrite without `--replace`, preview until `--yes`) and print the template structure check; `--dry-run` exits 1 when that check fails. An imported agent is written as a **manifest card** (was a legacy card). A valid agent template file still installs directly, but is now refused on a BLOCK finding.
- **`agentos skills show <id>`** (installed card, else the catalog template). `agents show <id>` shows the catalog card when the agent is not installed.
- **`doctor --fix` gives legacy agent cards that byte-match the catalog their manifest** (the `agents manifest --from-catalog` rule; body byte-identical, other cards untouched).
- **`agentos --help`** shows only the 11 commands in five groups (Setup & health, Work loop, Knowledge, Team, Optional & maintenance); `init --yes` is documented.

### Fixed

- `agentos --help` claimed the legacy migration paths were "removed in 2.0.0" although 2.0.0 shipped them (they are removed in 3.0.0, see above).
- `brain preview` exits 1 when validation rejects the proposal (as `brain validate` did).
- A `knowledge.brain.approval.exclude` list under `manual` or `auto-append` is ignored with a warning (`brain policy` shows it; `--json` `warnings`) instead of invalidating the policy; policy hashes are unchanged.
- The engine matrix's `launch` row reads "AgentOS never launches an engine process" (it said "there is no `agentos run`").
- `agents add <file> --dry-run` and `skills add <file> --dry-run` exit 1 on a file that is not a valid template (they printed `Validation: FAIL` but exited 0).

## [2.0.0] - 2026-10-27

Project Brain (PR #57) and the opt-in Brain approval policy for automatic append updates (PR #60). The Brain works without Obsidian, and Obsidian stays an optional second location. Upgrade: run `agentos doctor --fix` once to refresh the adapters and `.agentos/guide.md`, then check the breaking changes below. Migration: `docs/migration-project-brain.md`. Acceptance: `docs/project-brain-acceptance.md`.

### Breaking changes

- **`agentos brain apply` requires `--by <owner>`.** A real apply without it (or with an empty value) is refused with exit 1 and writes nothing; scripts that call `brain apply` must add `--by`. `--dry-run`, `preview` and `validate` are unchanged. The record's `history` line format changed to `<time> applied <proposal> by <applier> (proposed by <proposer>): <old> -> <new>`.
- **`agentos resume --task <id>` with no checkpoint exits 0** (`Status: clean start …`) instead of 1. Scripts that used the exit code to detect "no checkpoint" must read the output instead.
- **The vault host path moves to git-ignored `.agentos/local.yaml`.** `obsidian link`, `obsidian link-workspace`, `obsidian init --dir <outside>` and new setups write it there instead of `project.yaml`. A clone without `local.yaml` reads the integration as off (`obsidian status` exits 1 and says how to bind). `obsidian link` rewrites `knowledge.obsidian` to `mode: workspace-folder` and replaces a legacy `linked:` list with `linked: []` (the linked notes are not touched; copy the list first if you need it). A legacy absolute `vault` in `project.yaml` keeps working.
- **`agentos init` (new or `--existing`) now creates or adopts Brain records**: it registers AgentOS-owned files in place and writes `(unknown — fill in)` templates for the gaps. It never edits covering docs, and a re-run is a no-op.
- **A corrupted `.agentos/project.yaml` now fails** `brain`, `context`, `checkpoint` and `resume` instead of reading as an empty project.
- **`checkpoint --check <cmd> --cwd <dir>`** refuses a directory outside the workspace, also with `--dry-run` (which used to echo it), and `--cwd` is now workspace-root-relative from any subdirectory.
- **`agentos context` output changes:** without a `task_scope` it prints `Edit scope: not set (…)` instead of `(none; read-only task)`; it opens with a project overview from `.agentos/memory.md`; a record already shown by section is omitted as `covered` (`--json`: reason `covered` with `via`) instead of `no-match`.
- **`agentos <command> --help` / `-h`** prints that command's usage and exits 0, running nothing, instead of failing with `Unknown option: --help`.
- **Checkpoints from before 2.0.0 lose their current test receipts.** Fingerprints now hash changed-file contents, so `resume` lists an older checkpoint's passes as `stale (recheck)` even on an unchanged tree, and while changed files exceed the read bounds or cannot be read, every receipt is stale. Re-run the checks (`agentos checkpoint --task <id> --check "<cmd>"`) after upgrading.

### Added

- **Setup and discovery (slice 3).** `agentos init` (new or `--existing`) also sets up the Brain. Existing records are kept, AgentOS-owned files are registered in place, covering docs (six fixed paths) are named with their `brain register` command and never edited, and only the gaps get `(unknown — fill in)` templates. Re-running it is a no-op. `agentos context` opens with a bounded project overview (`.agentos/memory.md`, cut at 1500 chars). There is one Brain per workspace: a nested project with its own `.agentos/` is never read by its parent. The bootloaders (`AGENTS.md`, `CLAUDE.md`, `.hermes.md`) name the startup loop, and the guide gains `## Setup and project knowledge`. `docs/{quickstart,brain,obsidian,engines,migration-project-brain}.md` ship in the package.
- **Machine-local vault binding.** `.agentos/local.yaml` (`obsidian.vault`, git-ignored via `.agentos/.gitignore`) wins over `knowledge.obsidian.vault` in `project.yaml`. `obsidian link`, `obsidian link-workspace` and `obsidian init --dir <outside>` write the host path there. A clone without it reads the integration as off (`obsidian status` exits 1 and says how to bind). A legacy absolute `vault` in `project.yaml` keeps working.
- **Refreshable Obsidian index note and recovery (slices 2–3).** The index note is human prose plus one generated block (`agentos:brain-index` markers). Every Brain write rewrites only that block, and only when its bytes change. `agentos brain index [--adopt] [--dry-run]` recreates a deleted note or `index.json` from the records. An older unmarked note is changed only with `--adopt`, after a preview, and damaged markers are never written. An external-vault index note is labelled navigation only (`tags: [agentos-navigation]`). Setup prints whether the Obsidian app is on `PATH` (advice only).
- **Checkpoint-driven knowledge proposals (Project Brain goal slice 5).** `agentos brain propose <id> --from <file> --task <id>` ties a proposal to the task's current checkpoint (`task`, `checkpoint`, `evidence`: changed paths and receipt states); a progress-only checkpoint (no changed file, no `observed-pass` check) stages nothing, and re-staging the same event is a no-op (`duplicate: true`). The checkpoint output, the startup loop and `.agentos/guide.md` ask the engine to review whether completed work changed durable knowledge — an instruction, not a runtime hook; AgentOS calls no model and `apply` stays the owner's step. Run `agentos doctor --fix` to refresh the adapters and guide. See `docs/brain.md#knowledge-upkeep-at-completion`.
- `docs/migration-project-brain.md`: moving `link-obsidian` setups to `obsidian link` and `local.yaml`, relocating vault-canonical records before disabling the integration (a manual, reviewed move; never a second copy), and WSL paths.
- CI: a native Windows job (Node 24, `windows-latest`).
- Opt-in `knowledge.brain.approval` policy (`manual` by default, or `auto-append` with exact actor/record allowlists). `brain policy` explains it; `brain preview|validate|apply --auto --by <self>` evaluates it. Small append-only updates to accepted workspace notes/features can apply after current observed-pass checkpoint evidence. Architecture, decisions, conventions, replacements, supersession, stale/missing evidence and detected conflicts require review. Refusals preserve pending proposals. History and applied metadata retain declared actors, approval mode and policy hash; this is not authenticated identity or a sandbox.
- Engine bootloaders, context, checkpoint output and the packaged Brain guide explain policy-based upkeep. Existing manual application and checkpoints stay available; agents must not change policy or bypass a refusal.

### Changed

- **`agentos brain apply` needs an explicit `--by <applier>` (trial defect D6).** Without it (or with an empty value) a real apply is refused, exit 1, zero writes; `--dry-run`, `preview` and `validate` are unchanged. The record's `history` line is now `<time> applied <proposal> by <applier> (proposed by <proposer>): <old> -> <new>` (it used to credit the proposer as the applier) and the applied proposal gets `applied_by`. The checkpoint knowledge line, the startup loop, the guide and the usage say engines never run `brain apply`; the owner runs `brain apply <proposal> --by <owner>`. This is an instruction plus an audit trail, not enforcement: an engine can still pass `--by`. Scripts that call `brain apply` must add `--by`. Run `agentos doctor --fix` to refresh the adapters and guide.
- `agentos resume --task <id>` with no checkpoint and no evidence of work now exits 0 with `Status: clean start …` (was exit 1); it still invents no prior work.
- `agentos context` without a `task_scope` prints `Edit scope: not set (no task_scope in .agentos/project.yaml). Edit only the files the owner's task names; ask the owner to set task_scope.` instead of `(none; read-only task)`, and the guide says the same (trial defect D5). No default edit scope is invented, and a declared scope prints as before.

### Fixed

- **`agentos context` no longer reports a Brain record as `no-match` while showing its file (trial defect D7).** A record whose file is already shown section by section (e.g. `brain:decisions` and the `decision:*` sections of `.agentos/decisions.md`) is listed under Omitted as `covered by <section id> (same file, shown above)`; in `--json` the reason is `covered` with `via`.
- **Native Windows.** Three product bugs behind 17 of the first Windows CI run's failures (rollback tracking missed Windows siblings, `checkpoint --cwd` vs an 8.3 short-name root, a backslash boundary path in `migrate claude --preserve`), tests made portable, `.gitattributes` for LF checkout, and `npm run test:metadata` spawning `npm` through a shell on win32. See `docs/evidence/windows-validation.md`.
- **Trial defects D1–D4 (Project Brain trials, `docs/evidence/project-brain-trials.md`).** D1: `agentos <command> --help` / `-h` (also after a subcommand, e.g. `brain propose --help`) prints that command's usage and exits 0 instead of `Unknown option: --help`; it runs nothing. D2: `checkpoint --check <cmd> --cwd <dir>` accepts an absolute path inside the workspace and records it workspace-relative; `--cwd` is workspace-root-relative from any subdirectory; a path outside the workspace is refused, also with `--dry-run` (which used to echo it). D3: the Obsidian index note marks Brain records outside the vault folder (`— outside this vault: edit in your editor`) and says how to keep a record editable in Obsidian (`brain register <vault folder>/<note>.md`); no copies or moves. D4: under WSL, `obsidian init|link|status` also print the vault's Windows path (`/mnt/<d>/…` → `<D>:\…`, other paths → `\\wsl$\<distro>\…`).
- **Reliability (slice 2).** `obsidian status` resolves a relative vault against the workspace root, so it agrees from any subdirectory. An unreadable directory or vault folder (EACCES, I/O) is no longer read as empty: records `index.json` last knew there are `unreadable`/Missing, and absent, unreadable and emptied vault folders are reported differently.
- A stale proposal rejection names the actual cause (the record body drifted, or the base was re-verified). `brain list` no longer doubles the parentheses for unreadable records.
- **Project Brain independent of Obsidian (Project Brain slice 1).** An absent, disabled (`knowledge.obsidian.enabled: false`, new) or invalid `knowledge.obsidian` block no longer blocks `brain`, `context`, `checkpoint` or `resume`; an invalid block is a `doctor` problem and a `context --json` warning. With `canonical: workspace` a missing linked folder is a warning, not Missing, so `context --require-complete` passes. Records whose only copy is in an offline vault, or in a vault the integration no longer reads, stay under Missing. A corrupted `.agentos/project.yaml` now fails those commands instead of reading as an empty project. A Brain write is kept when regenerating `.agentos/brain/index.json` fails (reported as stale). See `docs/brain.md#independent-of-obsidian`, `docs/project-brain-acceptance.md`.
- Checkpoint fingerprints include bounded changed-file content hashes, so same-length code edits invalidate test receipts. Incomplete content evidence is treated as stale and cannot authorize automatic Brain application. Older checkpoints remain readable but need fresh checks before their receipts are current.

## [1.1.0] - 2026-10-26

Everyday-use fixes on top of 1.0.0 (PR #55). Upgrade: run `agentos doctor --fix` to get the new `.agentos/guide.md`; settings synced by 1.0.0 have no sync record, so re-run `agentos agents sync <engine> --role <id> --replace` once.

### Added

- **Sync record and synced-config freshness in `doctor` (1.1 slice 1).** `agents sync <engine>` (not `--dry-run`) also writes `.agentos/synced/<engine>.json` in the same mutation transaction: engine, role, scope (`--scope` flag and effective edit/read), AgentOS version, and per generated file its sha256 (plus the generated `permissions.allow`/`deny` entries). One shared check compares the installed files with the record and the record with what sync would generate now for the **recorded** role and scope: `OK`, `STALE` (per file: `tree changed`, `scope changed`, `manifest changed`, `generated entry edited`, `generated file missing`; or `synced by 1.0.0 without a record`), `INVALID` (broken record, invalid JSON settings, malformed `project.yaml`, card without manifest — with the reason), `MISSING` (never synced), `UNSUPPORTED`. `agentos doctor` prints one warning per stale or invalid engine naming the exact re-sync command (exit status unchanged, nothing rewritten; a never-synced workspace gets byte-identical output) and `doctor --json` adds `synced_config: [{engine, status, role, files, reason, user_entries}]`.
- **Safe agent re-sync (1.1 slice 2).** `agents sync <engine>` takes ownership from the sync record: on re-sync it replaces exactly the recorded `permissions.allow`/`deny` entries with the newly generated ones (owner entries keep their place and order, other keys untouched, indent and trailing newline kept), replaces `.claude/agents/<role>.md` while it still matches the recorded sha256, replaces only the Codex role block, and removes files recorded for a previous role (one record, one role per engine; the output says so). Hand-edited generated content, a 1.0.0 sync without a record, or an existing different list refuses with zero writes, naming the entries and `--replace`; `--replace` overwrites only that content (without a record: takes over `allow`/`deny` wholesale) and backs each overwritten file up once under `.agentos/runs/replaced-synced/<timestamp>/`. Files, backups and the record are written in one mutation transaction (rolled back on failure). `--dry-run` prints per-file `+`/`-` entries or `whole file replaced`/`Unchanged:` and writes nothing.

### Changed

- **Workflow guide names the v1 loop (1.1 slice 3).** The generated `.agentos/guide.md` now tells engines, one line per job: `agentos context <engine> --task "<task>" --role <id>` after `status`; ask the owner for `task_scope` when the edit scope is none (engines do not edit `project.yaml`); `agentos checkpoint --task <id> --progress … --next … --check "<cmd>"` before stopping or switching engines, `agentos resume --task <id>` to continue, `checkpoint --recover` when none was written, and why these are preferred over `run handoff`; `agentos brain propose …` (engines propose, the owner runs `brain preview`/`brain apply`); `agentos agents sync <engine> --role <id> --dry-run` and re-running the command `doctor` prints on `Synced config: STALE`. The guide grows from 3,333 to 4,601 bytes (budget 4,608, test-enforced), and every command and flag in it is checked against the CLI option allowlist. `doctor` reports a 1.0.0 guide as stale; `doctor --fix` refreshes only its managed block. Root adapters are unchanged.
- **STALE line names the command that works (1.1 slice 2).** `doctor` and `context --require-synced-config` print `re-run agentos agents sync <engine> --role <id> [--scope '<a,b>']` (scope single-quoted) and add `--replace` only when the plain re-sync would refuse (generated entry edited; 1.0.0 sync without a record). The old "remove permissions.allow/deny first" / "delete … first" hints are gone. Sync refusals now read `REFUSED:` with one line per file (`generated entry edited (…)`, `no sync record owns permissions.deny`) instead of the add-keys-only conflict dump.
- **`context --require-synced-config` uses the shared check.** It now covers `permissions.allow`, `.claude/agents/<role>.md` and the Codex role block (`agents sync codex`; codex was `UNSUPPORTED`), checks against the synced role/scope instead of the current call's (a `context` for another role no longer reports `STALE`), ignores owner-added entries (`user entries: N`), and reports `INVALID` with the reason instead of `MISSING` for errors. The OK line names the role: `Synced config: OK (<engine>, role <id>, sha256 <8>)`; `--json` `synced_config` may carry `role` and `reason`. Syncs made by 1.0.0 have no record and report `STALE` until re-synced (`docs/migration.md`).

## [1.0.0] - 2026-10-25

**AgentOS v1** (PRs #52 and #53, built from the stacked slices #46–#51).

**Deprecation retargeted:** the legacy upgrade paths deprecated in 0.9.0 are still present and still deprecated; their removal moves from 0.10.0 to 2.0.0 (removing flags inside 1.x would break semver). The whole 1.x line keeps them, so the migration route is now `npx agentos-for-projects@1 doctor --fix` (`@0.9` still works). Deprecation notices and `migration.deprecations[].removed_in` / `last_supporting` change to `2.0.0` / `1`.

 Five priorities — task-specific context, checkpoints and resume, a managed Project Brain, agent manifests with an engine capability matrix, optional Obsidian — plus correctness fixes, validated by a real cross-engine trial (Claude Code 2.1.310 ⇄ Codex 0.156.1, n=1; `docs/evidence/2026-10-25-cross-engine/`). Adoption is opt-in per command; a 0.9.0 workspace keeps working unchanged (`docs/migration.md`). Acceptance per priority and scenario: `docs/acceptance-matrix.md` (27 PASS, 0 FAIL, 0 BLOCKED after the closure re-trials T6–T8; n=1 per probe, T7 n=2 + controls). Backlog: `docs/improve-later.md`.

### Fixed

- **`context --require-enforcement` no longer passes on a matching synced config (v1 closure 3, owner review of PR #53).** Configuration presence is not proof of enforcement: AgentOS cannot verify workspace trust, new root-level files/dirs (until re-sync), `.agentos/` state and unrecognised shell writes stay writable, and the deny rules bind only Claude Code's own tools. `--require-enforcement` now exits 1 for every engine with `Enforcement: UNSUPPORTED — AgentOS cannot establish enforcement for <engine>: <reasons>`. The previous freshness check is `--require-synced-config` (`Synced config: OK (<engine>, sha256 <8>)` / `STALE` / `MISSING` / `UNSUPPORTED`); both flags may be combined (exit 1 if either fails); `--json` adds `enforcement: {status, reasons}` and `synced_config: {status, sha256?}`. The claude-code ADVISORY line names the residual writable paths.
- **`agents sync claude-code` no longer generates `Edit(/*)`/`Write(/*)` (v1 closure 2).** Host re-trial T6b: Claude Code 2.1.310 matches `/*` recursively, so with those two rules every probe item was denied, including edits inside the edit scope (`web/src`). ## [0.5.0] - 2026-09-14

### Compaction

- **Opt-in structural rewrite.** `agentos compact --rewrite` is the first mode that reduces live context. It archives `.agentos/handoff.md` and `.agentos/tasks.md` byte-for-byte under `.agentos/runs/compact-rewrite-<sha256>/` (raw files, `manifest.json`, `README.md`), verifies the archive hashes, rechecks the sources, and only then replaces live state inside the existing mutation transaction. Plain `agentos compact` keeps its conservative checkpoint behaviour.
- **Nothing active is guessed away.** The selected objective keeps its original heading, every unfinished task keeps its nested details, unclassified sections are re-emitted verbatim under `## Preserved context`, and constraint lines found inside archived history (`do not`, `never`, `requires approval`, `before merging`) are carried forward verbatim. Only superseded objectives and explicit history sections (`Previous …`, `Superseded …`, `Done`) move to the archive, and only when they hold no unchecked task block.
- **Ambiguity blocks instead of choosing.** With more than one `## Current objective` heading the command lists every candidate with a content-bound id, exits 1, and writes nothing until `--objective <id>` names one. Missing, empty, fenced-broken, non-UTF-8, non-regular, or symlinked live state also refuses with zero writes. `--expect-state <sha256>` binds an apply to the reviewed preview so a context update in between cannot be silently overwritten.
- **Honest reporting.** Before/after per file, archived/live/preserved counts, carried-forward constraints, and missing canonical sections are printed; growth is reported as growth (`… chars added`) instead of negative savings, and an apply with nothing to archive says it is a structural normalization only. A repeat rewrite of unchanged state is a write-free no-op.


### Migration UX (upgrading an older workspace)

- `doctor` / `doctor --json` report a read-only **migration inventory** — `migration.adapters`, `migration.repoIds`, `migration.retiredCards`, `migration.summary` — so an owner can see everything an older workspace still needs migrated before approving anything. It is report-only: no writes, and no change to doctor's exit status.
- New `agentos adapters explain <file>` reports the classification, managed-block status with byte offsets, the reason for a conflict, the legacy section span, and the next command for one adapter path — including when `.agentos/project.yaml` fails validation.
- **Adopting custom-content adapters.** An adapter that holds custom project knowledge with a stale AgentOS section interleaved in it is now classified `adopt` instead of an ownership conflict. `agentos doctor --fix --adopt-custom-adapters` replaces only that byte span — custom bytes before and after it are preserved verbatim and one `.agentos.bak` is written — and `agentos doctor --fix --dry-run` previews every planned adapter change read-only. A plain `doctor --fix` still refuses and names the flag.
- **Repository ID normalization.** `agentos doctor --fix --normalize-repo-ids [--dry-run]` renames a non-canonical repo ID (`frontend_client` → `frontend-client`) together with its repo note, preserving every other byte of `project.yaml` (comments, quoting, key order), and records an audit note under `.agentos/runs/`. It refuses with zero writes on any ambiguity: colliding IDs, both note files present, or a mapping that cannot be edited line-by-line.
- **Retired card cleanup.** Retired skill cards now carry per-card eligibility — `prunable` when their bytes hash-match a card body a real AgentOS version installed, `manual-review` otherwise. `agentos doctor --fix --prune-retired` removes only provably-generated cards, leaves forks reported and untouched, and rebuilds the local-skills index in `.agentos/skills.md`.

### Changed

- A non-canonical repository ID is no longer a parse-time failure that blocks every command: it is a reported, fixable `doctor` problem, so the rest of the diagnostics (adapter scan, agents, tasks, git state) still run. Genuinely unmigratable configs still fail closed exactly as before.

### Fixed

- `doctor` recognizes documented objective heading variants such as `## Current objective — 2026-09-15 (latest): …` instead of warning that the section is missing. It now distinguishes a missing objective from a present-but-empty one, and reports duplicate objective headings with every source line, without rewriting state from a diagnostic.
- Repository IDs are written into file paths (`.agentos/repos/<id>.md`) and into generated cards, so they are validated as safe workspace-relative path fragments with a conservative character set; a key like `../../../victim` can no longer create or delete a file outside the workspace.
- `doctor --fix --normalize-repo-ids` now runs the workspace boundary preflight like every other mutating command, so a symlinked `.agentos/repos` cannot redirect the rename out of the workspace.

## [0.4.0] - 2026-09-14

### Agents

- Consolidated the agent catalog to six roles with distinct responsibility boundaries:
  - **planner** (was `project-manager`) — planning-only; does not implement, edit source, commit, or push.
  - **developer** (was `implementation`; absorbs `frontend-engineer` and `backend-engineer`) — implements scoped changes in the assigned repo using the relevant frontend/backend skills; does not claim independent QA or review.
  - **tester** (was `qa`) — independent verification; may author tests when assigned; reports defects without silently fixing the implementation under test.
  - **reviewer** (was `code-reviewer`) — read-only review unless reassigned.
  - **release-manager** — explicit authorization per commit/push/merge/publish; exact-path staging; remote read-back.
  - **security-reviewer** — optional specialist, not auto-enabled.
- `detected`/`minimal` profiles now install `developer`, `tester`, `reviewer`, `release-manager` (no longer add frontend/backend specialists).

### Skills

- Consolidated 20 skills into 15 framework-agnostic workflow skills:
  - core: `debugging`, `test-driven-development`, `git-safety`, `verification`, `documentation`, `code-review`
  - frontend: `frontend-design`, `frontend-testing`
  - backend: `backend-development`, `backend-testing`, `authorization`
  - fullstack: `integration-testing`
  - github: `pull-request-workflow`, `commit-messages`, `ci-verification`
- Core skill instructions are framework/provider-neutral; framework-specific guidance (NestJS, Nuxt, GitHub, Conventional Commits) lives in optional `references/` loaded only when relevant to the assigned repo.
- `git-safety` now absorbs secret-handling safeguards (was `secret-scanner-safe-edits`).
- `commit-messages` is a generalized, read-only, staged-first workflow that discovers project commit conventions instead of hardcoding them.
- `frontend-design` merges `ai-slop-design-review` + `interface-feel-polish`; `frontend-testing` merges `frontend-build-verification` + `nuxt-e2e-testing`; `backend-development` generalizes `nestjs-feature-implementation`; `backend-testing` generalizes `backend-service-verification`; `authorization` generalizes `nestjs-auth-guards`; `code-review` merges `requesting-code-review` + `backend-pr-review` + `github-code-review`.

### Catalog mechanics

- Package Markdown templates are now the single canonical source for skills and agents; `skills add`, `templates copy`, and `agents add` produce equivalent complete workflows (previously two competing inline/file sources could drift).
- Summary mode no longer truncates workflow steps; it preserves every safety and completion gate.
- Skill `references/` are installed alongside their `SKILL.md` (previously dangling paths).
- Deprecated agent/skill aliases resolve to canonical IDs with deprecation notices and dedupe.
- `doctor` detects legacy IDs; `doctor --fix` migrates only byte-matched historical card shapes, preserving customized cards and native engine copies.
