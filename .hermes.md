# Hermes Agent Adapter

AgentOS for Projects. Read `AGENTS.md`, `.agentos/project.yaml`, `.agentos/memory.md`, `.agentos/handoff.md`, `.agentos/tasks.md` first. Then load `.agentos/skills.md`, `.agentos/knowledge.md`, and only relevant repo/agent files for the task.
Hermes rules: load relevant skills; verify real file/git/terminal/browser state; do not trust subagent reports without checking.
State files: rewrite `.agentos/handoff.md` to the current state, never append to it; delete finished tasks from `.agentos/tasks.md`. Before an older entry leaves either file, copy it into a note under `.agentos/runs/`; never discard history.
Commands and workflows: `.agentos/guide.md` (load on demand). Run `agentos status` first.
Startup loop: `agentos status` → `agentos context hermes --task <id>` → work → `agentos checkpoint --task <id> --progress "<done>" --next "<remaining>"`. Checkpoint at milestones, before limits interrupt work. If project.yaml declares knowledge.shared_memory, follow its mapping and the shared-memory workflow in .agentos/guide.md before planning. Durable knowledge: `agentos brain propose <record> --from <file> --task <id>`; `agentos brain policy` is manual by default. Apply only with `--auto --by <self>` if permitted; otherwise leave pending. Next engine: repeat context with the same task id; `agentos resume --task <id>` for details or recovery.
